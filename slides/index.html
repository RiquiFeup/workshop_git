Qual é a versão certa?

Um ficheiro muda. Duas pessoas editam. De repente, o nome do ficheiro é a única memória do trabalho.

Num relatório, num script ou num protocolo, precisamos de saber o que mudou, quando e porquê.

O Git nasceu de um problema de colaboração.

Em 2005, o desenvolvimento do Linux precisava de uma forma rápida e fiável de acompanhar muitas alterações feitas por muitas pessoas.

O Git organiza essas alterações numa história. Cada commit guarda um passo com uma mensagem que explica o que mudou.

pessoa Apessoa Bpessoa C
alterações de várias pessoasuma história organizada

Fonte: Pro Git · Short History of Git

git status

Pergunta ao Git: “O que está diferente agora?”

É o comando para te orientares. Podes usá-lo antes e depois de cada passo.

Terminal

$ git status

Changes not staged for commit:

modified: exercicio/README.md

O README foi alterado, mas ainda não foi escolhido para o próximo commit.

git add

Escolhe que alterações entram no próximo commit.

Hoje vamos escolher apenas o README que cada pessoa editou.

git commit

Guarda as alterações escolhidas como um passo na história.

A mensagem ajuda outras pessoas — e o teu “eu” do futuro — a perceber o que fizeste.

$ git commit -m "Personaliza o meu README"

Branch

Uma branch é outra linha de trabalho no mesmo repositório.

Podes experimentar uma mudança na feature enquanto a main continua no seu caminho. No exercício, vamos ficar na main.

Entender branches ↗
linha principal experiência em paralelo

Clica para abrir uma linha de trabalho paralela.

git merge

Junta o trabalho da feature à main.

Estás na main. Depois do merge, a linha principal também inclui o trabalho feito na feature.

14:35–15:00 · preparação

O commit precisa de um autor.

Escolhe o nome que queres mostrar no histórico. Para o email, podes usar o endereço noreply da tua conta GitHub.

Substitui os exemplos antes de executar. Nunca escrevas uma password ou token nestes comandos.

No terminal, escreve:

git config --global user.name "O Teu Nome"git config --global user.email "O_TEU_EMAIL_OU_NOREPLY"

Encontra o teu endereço noreply em GitHub → Settings → Emails ↗.

git config --global user.name

Conseguiste? O último comando mostra o nome que escolheste.

Ajuda durante a prática

Ficaste bloqueado?

Abre a dúvida que corresponde ao que estás a ver. Mostra a mensagem de erro a quem te está a apoiar.

“not a git repository”

Entra na pasta clonada: cd workshop_git. Depois repete git status.

Push: 403 ou “Permission denied”

Executa git remote -v. origin deve incluir o teu utilizador, pois tens de clonar o teu Fork.

O commit pede nome e email

Volta ao slide «Identidade Git» e configura ambos. Podes usar o email noreply do GitHub.

“nothing to commit”

Confirma que editaste e guardaste exercicio/README.md dentro da pasta clonada. Se já fizeste o commit, segue para git push.

O VS Code não abre

Volta ao slide 16 e usa o link para a instalação oficial. Se o computador bloquear a instalação, pede apoio.

“CONFLICT” em pull ou merge

O Git encontrou alterações incompatíveis no mesmo ficheiro. Mantém os ficheiros e pede apoio antes de continuar.
