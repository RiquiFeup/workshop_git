O Git nasceu de um problema de colaboração.

Em 2005, o desenvolvimento do Linux precisava de uma forma rápida e fiável de acompanhar muitas alterações feitas por muitas pessoas.

Git é a história do projeto.

Cada commit é um ponto guardado nessa história: alterações escolhidas, com uma mensagem que explica o passo.

O Git não guarda todas as alterações automaticamente. Tu decides quando criar cada commit.

git status

Pergunta ao Git: “O que está diferente agora?”

É o comando para te orientares. Podes usá-lo antes e depois de cada passo.

Terminal

$ git status

Changes not staged for commit:

modified: exercicio/README.md

O README foi alterado, mas ainda não foi escolhido para o próximo commit.

git add

Escolhe que alterações entram no próximo commit.

Hoje vamos escolher apenas o README que cada pessoa editou.

14:30–15:00 · preparação

O commit precisa de um autor.

Escolhe o nome que queres mostrar no histórico. Para o email, podes usar o endereço noreply da tua conta GitHub.

Substitui os exemplos antes de executar. Nunca escrevas uma password ou token nestes comandos.

No terminal, escreve:

git config --global user.name "O Teu Nome"git config --global user.email "O_TEU_EMAIL_OU_NOREPLY"

Encontra o teu endereço noreply em GitHub → Settings → Emails ↗.

git config --global user.name

Conseguiste? O último comando mostra o nome que escolheste.

15:05–15:10 · cópia local

Traz o teu Fork para o computador.

Na página do teu Fork, clica em Code → HTTPS e copia o endereço.

No terminal, escreve git clone, um espaço e cola o endereço. O URL tem de conter o teu utilizador.

git clone https://github.com/TEU_UTILIZADOR/workshop_git.git

O comando acima é um exemplo. Substitui TEU_UTILIZADOR ou usa o URL copiado em Code.

cd workshop_git
git remote -v

Conseguiste? origin aponta para TEU_UTILIZADOR/workshop_git.

15:18–15:21 · verificar e escolher

Vê a mudança. Depois escolhe-a.

status mostra o que mudou. add escolhe o README para o próximo commit.

Executa os comandos dentro da pasta workshop_git, um de cada vez.

15:21–15:27 · guardar e enviar

Guarda uma versão. Envia-a.

commit grava a versão no computador. push envia-a para o teu Fork no GitHub.

Se o navegador pedir autenticação, entra na tua conta. Não partilhes códigos nem credenciais.

git commit -m "Personaliza o meu README"
git push origin main

Conseguiste? O terminal indica que main foi atualizado.

Se houver erro, abre a ajuda ↗
15:27–15:30 · confirmar

Encontra o teu commit.

git log mostra as versões guardadas. Depois abre o teu Fork e procura a mesma mensagem no GitHub.

O teu commit deve ser o primeiro da lista.

git log --oneline -5
8b3c1a2 Personaliza o meu README931369f Build Git and GitHub workshop materials

Ajuda durante a prática

Ficaste bloqueado?

Abre a dúvida que corresponde ao que estás a ver. Mostra a mensagem de erro a quem te está a apoiar.

“not a git repository”

Entra na pasta clonada: cd workshop_git. Depois repete git status.

Push: 403 ou “Permission denied”

Executa git remote -v. origin deve incluir o teu utilizador, pois tens de clonar o teu Fork.

O commit pede nome e email

Volta ao slide «Identidade Git» e configura ambos. Podes usar o email noreply do GitHub.

“nothing to commit”

Confirma que editaste e guardaste exercicio/README.md dentro da pasta clonada. Se já fizeste o commit, segue para git push.
